### 1.2 技术架构设计

#### 核心架构模式：**MVC + 事件驱动 + 组件系统**

```
┌─────────────────────────────────────────────────────────┐
│                     JavaFX Application                    │
│                   (主窗口/游戏循环)                       │
└──────────────────────┬──────────────────────────────────┘
                       │
        ┌──────────────┴──────────────┐
        │                             │
┌───────▼────────────┐      ┌────────▼──────────────┐
│  GameEngine        │      │   InputHandler       │
│  (核心逻辑)        │      │  (输入处理)          │
└───────┬────────────┘      └────────┬──────────────┘
        │                             │
        │  update()                   │
        │  render()                   │
        │                             │
    ┌───┴──────────────────────┬─────┴────────────┐
    │                           │                  │
┌───▼──────────┐    ┌──────────▼──┐    ┌─────────▼──┐
│ WorldSystem  │    │ CombatSystem │    │  UIManager │
│(地图/NPC)    │    │  (战斗逻辑)  │    │ (菜单/HUD) │
└───┬──────────┘    └──────┬───────┘    └─────┬──────┘

          ↓           ↓           ↓
      ┌───────────────────────────────────┐
      │    ResourceManager                 │
      │  (图形/音效/配置缓存)              │
      └──────────────┬────────────────────┘
                     │
      ┌──────────────┴────────────────┐
      │                               │
```

### 1.3 关键设计决策

| 方面 | 选择 | 理由 |
|------|------|------|
| UI框架 | JavaFX而非Swing | 现代化、支持CSS、性能优于Swing、官方支持更好 |
| 图形方式 | 纯代码生成（Canvas/GraphicsContext） | 无外部资源依赖、文件体积小、便于修改 |
| 存储方案 | SQLite + JSON序列化 | 存档灵活、配置易读、零依赖 |
| 多线程 | GameThread + FX Application Thread | 分离游戏逻辑和UI线程，避免UI卡顿 |
| 事件系统 | 观察者模式自实现 | 解耦系统，支持灵活的事件流 |

## 二、分阶段实现计划

### 第一阶段（1.5周）：核心框架搭建

#### 阶段目标
- 建立JavaFX游戏窗口和基础渲染循环
- 实现MVC架构基础类
- 完成输入处理系统
- 输出：60 FPS稳定运行的空游戏窗口

#### 具体任务

**2.1.1 JavaFX项目初始化**

步骤：
1. 创建Maven项目结构
2. 配置`pom.xml`依赖：
   - javafx-controls:21.0.2
   - javafx-graphics:21.0.2
   - javafx-fxml:21.0.2
   - sqlite-jdbc:3.45.0
   - jackson-databind:2.16.1
   - junit-jupiter:5.10.2
   - testfx:4.0.17

3. 创建主类`PotatoAdventure.java`
   - 继承`javafx.application.Application`
   - 实现`start(Stage stage)`方法
   - 设置窗口标题、大小（1280x720）
   - 设置canvas容器和root scene

**2.1.2 游戏循环实现**

实现`GameEngine`类：
- 管理游戏状态（MENU、RUNNING、PAUSED、GAME_OVER）
- 实现update()方法（游戏逻辑更新）
- 实现render()方法（画面渲染）
- 使用`AnimationTimer`驱动60FPS循环
- 实现deltaTime计算，确保帧率无关的游戏逻辑

代码结构示例：
```
GameEngine {
  - gameState: GameState
  - deltaTime: double
  - fps: int
  - update(deltaTime)
  - render(gc: GraphicsContext)
  - start()
  - stop()
}
```

**2.1.3 输入处理系统**

创建`InputHandler`类：
- 监听键盘事件（KeyPressed、KeyReleased）
- 监听鼠标事件（MousePressed、MouseMoved）
- 维护按键状态集合（Set<KeyCode>）
- 提供查询接口：`isKeyPressed(KeyCode)`、`getMousePos()`
- 支持按键绑定映射

**2.1.4 基础UI框架**

创建`Screen`抽象基类：
- `update(deltaTime)`
- `render(gc)`
- `onScreenEnter()`
- `onScreenExit()`

实现`ScreenManager`：
- 管理当前活跃Screen
- 支持Screen栈（用于返回前一个菜单）
- 提供`switchTo(Screen)`和`pushScreen(Screen)`方法

#### 第一阶段检查清单
- [ ] JavaFX窗口正常启动，标题栏显示"土豆冒险"
- [ ] 游戏循环稳定运行，FPS显示在25帧以上
- [ ] 键盘输入（WASD/方向键）能被检测
- [ ] 鼠标坐标能被实时获取
- [ ] 可通过Esc键返回菜单
- [ ] 代码通过静态分析工具（CheckStyle）检查

### 第二阶段（2周）：游戏世界与玩家系统

#### 阶段目标
- 实现地图系统（基于瓦片Tile）
- 实现玩家角色移动和碰撞检测
- 实现基础图形渲染
- 输出：能在地图上看到玩家并能移动

#### 具体任务

**2.2.1 地图系统设计**

核心类设计：
- `Tile`：单个地形瓦片（32x32像素）
  - 属性：type（草地、石头等）、walkable（是否可通行）、x、y坐标
  - 方法：getType()、isWalkable()、render()

- `TileSet`：瓦片集合（地图层）
  - 二维数组存储Tile：`Tile[][]`
  - 方法：getTile(x,y)、setTile(x,y,tile)、getWidth()、getHeight()

- `Map`：完整地图
  - 包含多层TileSet（背景层、障碍物层）
  - 包含对象层（NPC、宝箱位置）
  - 包含事件层（传送点）
  - 方法：load()、save()、getTile()、getCollisionAt()

- `MapManager`：地图管理器
  - 加载/卸载地图
  - 管理当前活跃地图
  - 处理地图切换

数据格式（JSON）：
```json
{
  "width": 50,
  "height": 40,
  "tileSize": 32,
  "layers": [
    {
      "name": "background",
      "data": [[0,0,1,1,...],[...]]
    },
    {
      "name": "collision",
      "data": [[0,0,0,1,...],[...]]
    }
  ],
  "objects": [
    {"type": "npc", "id": 1, "x": 10, "y": 15},
    {"type": "chest", "id": 1, "x": 20, "y": 10}
  ]
}
```

**2.2.2 玩家角色系统**

创建`Player`类（继承`Character`）：
- 属性：
  - 位置：x, y（像素坐标）
  - 体积：width, height（用于碰撞）
  - 属性：hp, mp, exp, level
  - 背包：inventory
  - 装备：equipment
  - 技能：skills

- 方法：
  - `update(deltaTime, input, collisionMap)`
  - `move(dx, dy)`
  - `takeDamage(amount)`
  - `heal(amount)`
  - `render(gc)`

实现细节：
- 移动时进行碰撞检测（AABB算法）
- 支持对角移动（同时按下多个方向键）
- 移动速度参数化（例如每秒120像素）

**2.2.3 碰撞检测系统**

创建`CollisionDetector`类：
- 实现矩形碰撞检测（AABB）
- 方法：`checkCollision(Rect a, Rect b) -> boolean`
- 优化：四叉树或网格划分加速碰撞查询

**2.2.4 图形生成与渲染**

- 实现`TileRenderer`：渲染地图瓦片
  - 根据tile type调用不同的绘制方法
  - 缓存生成的瓦片图像到`ImageCache`

- 实现基础图形生成器：
  - `GraphicsGenerator`：基础工具（颜色、笔刷等）
  - `PlayerGraphics`：生成玩家角色32x32图像
  - `EnemyGraphics`：生成敌人图像
  - `TerrainGraphics`：生成地形瓦片

- 实现`Renderer`主渲染器：
  - 按顺序渲染：背景层 → 障碍物 → 玩家 → UI
  - 实现摄像机系统（使玩家始终在屏幕中心）
  - 优化：只渲染视口内的对象

#### 第二阶段检查清单
- [ ] 能看到一个20x15的地图网格
- [ ] 玩家角色以32x32像素显示在地图上
- [ ] 用WASD/方向键可以移动玩家
- [ ] 玩家碰撞到障碍物时停止移动
- [ ] 摄像机跟随玩家移动
- [ ] 帧率稳定在60 FPS以上
- [ ] 代码覆盖率>70%（单元测试）

创建`CharacterStats`类：
- 基础属性：HP, MP, ATK, DEF, SPD, LUCK
- 派生属性：CritRate, DodgeRate（由基础属性计算）

创建`Experience`系统：

- 技能点分配

**2.3.2 战斗系统设计**

核心类：
- `Skill`：技能类
  - 属性：id、name、costMP、cooldown、damage公式、effect
  - 方法：calculateDamage(attacker, defender) -> int

- `StatusEffect`：状态效果
  - 属性：type（中毒、冰冻等）、duration（持续回合数）、value（效果值）
  - 方法：apply()、tick()、isExpired()

- `Battle`：单场战斗
  - 属性：attacker、defender、currentTurn、battleLog
  - 方法：
    - `executeAction(action, targets)`
    - `calculateDamage(source, target, skill)`
    - `applyEffect(target, effect)`
    - `endTurn()`
    - `isBattleOver() -> boolean`

- `CombatSystem`：战斗管理器
  - 方法：
    - `startBattle(player, enemy)`
    - `endBattle(victor)`
    - `rewardPlayer(player, loot)`

**2.3.3 背包与物品系统**

创建`Item`基类：
- 属性：id、name、rarity（品质）、description

创建`ItemFactory`：
- 根据物品ID生成物品实例

创建`Inventory`：

  - `getItem(itemId) -> Item`
  - `isFull() -> boolean`
  - `expandCapacity(slots)`

创建`Equipment`：
- 装备部位：武器、盔甲、手套、鞋子、饰品

**2.3.4 UI系统实现**

实现具体组件：
- `Button`：可点击按钮
- `Label`：文本标签
- `Panel`：容器面板
- `HealthBar`：血条显示
- `InventoryUI`：背包界面

实现主要UI屏幕：

- `GameScreen`：游戏运行界面

  - 类型：击杀X个敌人、收集X个物品、到达某地点
  - 属性：type、target、progress、completed

- `Quest`：任务本体
  - 属性：id、name、description、objectives[]、rewards、preQuests（前置任务）
  - 状态：AVAILABLE（可接）、ACCEPTED（已接）、COMPLETED（已完成）

- `QuestManager`：任务管理器
  - 方法：
    - `acceptQuest(questId)`
    - `abandonQuest(questId)`
    - `updateProgress(objectiveId, amount)`
    - `completeQuest(questId) -> Reward`
    - `getActiveQuests() -> List<Quest>`

**2.4.2 NPC与对话系统**

创建`NPC`类：
- 属性：id、name、position、questsOffered、dialogueTree
- 行为：巡逻、站立、交互

创建`DialogueNode`：
- 属性：text、responses[]
- 分支对话树结构

创建`DialogueSystem`：
- 管理对话状态
- 根据选择切换对话分支
- 支持条件判断（玩家等级、持有物品等）

**2.4.3 存档系统**

创建`SaveData`：
- 包含：玩家属性、背包、已完成任务、地图进度等

创建`SaveManager`：
- 方法：
  - `save(slot: int, data: SaveData)`
  - `load(slot: int) -> SaveData`
  - `deleteSave(slot: int)`
  - `getSaveInfo(slot: int) -> SaveInfo`

数据持久化：
- 主要数据保存为JSON（易读易编辑）
- 敏感数据使用SQLite（大数据量）
- 加密敏感存档（可选）

## 三、关键模块深度实现指南

### 3.1 战斗系统详细设计

#### 伤害计算公式
```
基础伤害 = (攻击方ATK × 1.5 + 技能基础伤害) - (防御方DEF × 0.5)
最终伤害 = 基础伤害 × (1 + 暴击倍数) × (1 + 属性克制倍数)
其中：
  - 暴击倍数：0 或 0.5（若CritRate检定成功）
  - 属性克制倍数：根据技能属性与敌人弱点
```

#### 状态效果应用
- 每回合检查状态效果
- 应用伤害/回复/属性修改
- 判断是否过期并移除

#### 回合制战斗流程
1. 玩家选择行动（攻击/技能/物品/逃跑）
2. 确定行动顺序（基于SPD属性）
3. 执行行动，计算伤害，应用效果
4. 检查战斗结束条件
5. 若未结束，重复步骤1

### 3.2 渲染管理与性能优化

#### 分层渲染架构
```
Layer 1: 背景（地形、静态装饰）- 低频更新
Layer 2: 动态对象（敌人、NPC、物品）
Layer 3: 特效（技能特效、爆炸）
Layer 4: UI（血条、文字浮伤）
Layer 5: 菜单（对话框、背包）
```

#### 性能优化策略
1. **对象池**：复用频繁创建销毁的对象（子弹、特效）
2. **脏标记**：仅更新变化的对象
3. **四叉树**：加速碰撞检测
4. **图像缓存**：缓存生成的图形到内存
5. **异步加载**：后台线程加载资源

## 七、常见问题与解决方案

### Q1: 如何实现平滑的人物移动？
A: 使用deltaTime（每帧的时间差）而非固定像素移动
```java
double movementSpeed = 120; // 每秒120像素
x += movementSpeed * deltaTime * direction.x;
y += movementSpeed * deltaTime * direction.y;
```

### Q2: 如何优化大型地图的渲染性能？
A: 实现视口裁剪（只渲染可见部分）
```java
int viewportX = (int)(player.x - screenWidth/2);
int viewportY = (int)(player.y - screenHeight/2);
// 仅渲染(viewportX, viewportY)范围内的瓦片
```

### Q3: 如何避免内存泄漏？
A: 
- 及时释放不用的资源（图像、音效）
- 取消事件监听器
- 使用try-with-resources（SQL连接）

### Q4: 战斗系统如何平衡？
A: 
- 建立Excel表格跟踪敌人等级与数值
- 使用参数化常数便于调整
- 频繁进行玩家测试反馈
